# Desktop Updates

A desktop app generated by `ph run desktop` used to be installed by hand, once per version. An `updates` block in `hosts/desktop/app.json` turns on the updater in the generated Tauri shell, and a signed `ph run desktop build` leaves the installers and a feed file in one folder for the release (powerhouse#3400).

```json
"updates": {
  "github": "example/notes",
  "pubkey": "<content of the .pub file `tauri signer generate` writes>"
}
```

## Status

**Unverified against a published release.** No published `@powerhousedao/desktop` carries #3400 yet: 6.2.3-dev.104 predates it. The tests and the demo skip themselves on a release without `collectRelease`, and `pnpm build` (tsc) fails against dev.104's types. Once a release includes #3400, pin it in `package.json`, regenerate the lockfile and remove this section.

The tests, the demo and `tsc` pass against the merged source of #3400. powerhouse's "Recipes E2E" job runs this recipe against the monorepo's own packages.

## How it works

| Step | Function | What the tests check |
|------|----------|----------------------|
| app.json | `appJsonSchema`, `loadAppJson`, `updateEndpoints` | `updates` omitted or `null` is off. Exactly one of `github` (`owner/name`) and `endpoints` (https only). `pubkey` must be a minisign public key: a pasted private key, or anything else, is refused with its own message. `github` becomes `https://github.com/<repo>/releases/latest/download/latest-{{target}}-{{arch}}.json` |
| Generated shell | `projectShell` | `tauri.conf.json` gets `bundle.createUpdaterArtifacts` and `plugins.updater` with the key, the endpoints and `requireSignedVersion: true`. `Cargo.toml` gets `serde_json`. `tauri.unsigned.conf.json` is written for a build without the key. The `update_*` commands are granted with or without updates. Turning updates off removes all of it |
| Download address | `releaseBaseUrl` | The GitHub release of the tag the workflow runs for (`GITHUB_REF_TYPE=tag`), else `v<version>`. `PH_DESKTOP_RELEASE_URL` overrides it and must be https. With `endpoints` and no override there is no address |
| Release folder | `collectRelease`, `releaseReport` | Installers are copied to `bundle/release/` under names GitHub keeps (a space becomes a dot). The macOS archive is renamed for its version and processor. Signed installers go into one feed file per system and processor, `latest-<os>-<arch>.json`. An unsigned installer is copied but left out of the feed and reported. Files older than the build are left out. No address, no feed |

The updater compares versions and checks each download's signature in the shell (`ph-desktop-shell` 0.1.2), so none of that runs here. The release folder is built from a fake `target/release/bundle`: `collectRelease` copies installers and reads `.sig` files as text, so placeholders show everything it does without running `tauri build`.

## Architecture

| Module | Purpose |
|--------|---------|
| `hosts/desktop/app.json` | The app's identity with `updates.github` and a generated public key |
| `src/keys.ts` | `releaseKeys`: an ed25519 public key in the `tauri signer generate` format, and a private-key lookalike for the refusal case |
| `src/updates.ts` | `updatesProblems` (the schema's messages for an `updates` block), `generateShell` (runs `projectShell` in a temporary host folder and reads back the updater's files), `fakeBundle` |
| `src/demo.ts` | Prints the schema's refusals, the generated updater settings, and the release folder and feed of a signed Linux build tagged `v1.2.0` |

## Releasing a real app

1. `tauri signer generate -w ~/.tauri/notes.key` (the Tauri CLI, `cargo tauri` or `@tauri-apps/cli`) writes the key pair. Put the `.pub` file's content in `updates.pubkey`.
2. In CI, set `TAURI_SIGNING_PRIVATE_KEY` (and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) and run `ph run desktop build` in one job per system.
3. Attach every file in `hosts/desktop/tauri-shell/target/release/bundle/release/` to the GitHub release of the tag.

Without the key, the build warns and makes unsigned installers that cannot be offered as an update.
